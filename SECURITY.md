# Security Policy

Grape Linux is an experimental research project. Public releases and announcements are not assurances that the software is ready for daily use.

## Reporting security issues
Please report suspected vulnerabilities privately using GitHub's **Report a vulnerability** option if it is enabled, or contact a project maintainer privately. Do not publish exploit details, private device information, access tokens, credentials, or unredacted logs in public issues.

## Scope
This public repository is a showcase. The core Linux development code and unpublished hardware research remain in a separate private repository. A public issue is not permission to test devices, accounts, networks, or external services you do not own.

## Contribution and publication rules
- Submit changes through a pull request.
- Code and documentation ownership is declared in `.github/CODEOWNERS`.
- The default branch is covered by a GitHub ruleset that blocks force pushes and deletion and requires pull requests for ordinary contributors.
- CODEOWNERS ownership **does not itself require a review**; mandatory code-owner approvals must be enabled separately in the GitHub ruleset when an independent reviewer is available.
- Do not place passwords, OAuth tokens, firmware dumps, private device identifiers, or protected research data in public content.
- Preserve the project's dated change history, using addenda and archives for corrections.

## Known boundary
Private repository read access and downloadable copies cannot be restricted using public showcase branch protections. Keep sensitive material only in authorized private repositories.
